PRMUSEUM MULTI-AGENT + LIVE SUBTITLE SETUP (v4.3)
==================================================

AVAILABLE UI SLUGS
------------------
Edward Bernays = bernays
Ivy Lee = ivy-lee
Walter Lippmann = lippmann
Arthur W. Page = arthur-page

IMPORTANT v4.3 CHANGE
---------------------
Portrait/name synchronization no longer depends on syncActiveAgent or setActiveAgent.
Do NOT rewrite your working Transfer Rules for the purpose of updating the webpage.

Restore/keep the transfer conditions that make the agents hand off reliably.
The webpage now observes ElevenLabs' own transfer_to_agent tool events and changes the
profile only after ElevenLabs reports that the transfer succeeded.

A. CLIENT EVENTS
----------------
For every agent that can START a PRMuseum conversation, go to:

Agent -> Advanced -> Client events

Enable:
- audio
- agent_tool_request
- agent_tool_response

`audio` is used for the word-timed subtitles.
`agent_tool_request` exposes the transfer_to_agent request and its destination number.
`agent_tool_response` tells the webpage whether the transfer actually succeeded.

ElevenLabs carries the starting/parent agent's client-event configuration across transfers,
but enabling the same three events on every PRMuseum agent is recommended because any one of
them may be selected as the starting agent.

B. TRANSFER RULES
-----------------
Keep or restore the Transfer Rules that were already working well for you.
The profile display does not require special transfer-rule wording.

The only requirement is that each agent still uses ElevenLabs' built-in transfer_to_agent
system tool for its handoffs.

C. REMOVE THE OLD DISPLAY-SYNC REQUIREMENT
-----------------------------------------
You may remove this old prompt behavior:
- call syncActiveAgent when becoming active
- call setActiveAgent when becoming active
- wait for a display-sync tool before speaking

You may also remove the syncActiveAgent / setActiveAgent client tools from ElevenLabs if they
were added only for portrait synchronization. The app keeps compatibility handlers, but v4.3
does not rely on them.

D. HOW THE PROFILE NOW FOLLOWS THE REAL TRANSFER
------------------------------------------------
1. Bernays (for example) calls ElevenLabs' built-in transfer_to_agent.
2. ElevenLabs sends agent_tool_request to the webpage.
3. The request includes the transfer destination number used by ElevenLabs.
4. The Vercel server reads Bernays' current ElevenLabs agent configuration and resolves that
   number to the actual destination Agent ID.
5. The old profile stays visible while the transfer is pending.
6. ElevenLabs sends agent_tool_response when transfer_to_agent finishes.
7. If the response reports success, the webpage switches to the resolved destination profile.
8. If the transfer fails, the old profile remains displayed.

Because spoken requests, typed requests and the right-hand menu all ultimately use
transfer_to_agent, they share the same synchronization path.

E. VERCEL BACKEND ENABLE / DISABLE
----------------------------------
Set, for example:

PRMUSEUM_ENABLED_AGENTS=bernays,ivy-lee,lippmann,arthur-page

An agent appears only when it is enabled above and has its ELEVENLABS_AGENT_* ID configured.

F. API KEY PERMISSIONS
----------------------
Enable BOTH of these on the Vercel ElevenLabs API key:

- ElevenLabs Agents / Conversational AI Read (convai_read)
- ElevenLabs Agents / Conversational AI Write (convai_write)

Write is used to obtain the WebRTC conversation token.
Read is used by /api/resolve-transfer to read the current transfer rule list from the actual
source agent, so the webpage does not have to hard-code your rule ordering.

No separate API permission is required for the client transfer events themselves.

G. LIVE SUBTITLES
-----------------
Keep the `audio` client event enabled. Subtitles continue to use audio alignment, reveal words
as they are spoken, and display no more than one sentence at a time.
